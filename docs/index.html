The two date fields are the window: the “to” calendar only offers days after the “from” date (earlier days and months are greyed out), and picking a departure date automatically sets the return end to departure + the longest stay, so the pair is always valid.
“Whole trip” (default) means a departure that could not return inside the window is neither searched nor listed — the stay length sets the return date.
A round-trip ticket is a single booking with Google's own round-trip total. Two separate one-ways sums the cheapest one-way out and the cheapest one-way back — often cheaper, but it is two tickets (possibly two different airlines) booked separately, each with its own baggage/change rules. Both searches and reports each, in its own section, so you can compare. Searching both costs extra lookups.

Background searches. A long sweep keeps running while you use other tabs or apps: the tab icon spins, the tab title shows the progress, and when the results are ready you get a browser notification (allowing notifications when asked makes this work even when the tab is hidden). On phones the page must stay open — iOS suspends background tabs entirely, so the run resumes when you return.

Tip: install it as an app. On iPhone/iPad open Share → Add to Home Screen, on Android ⋮ → Add to Home screen. You get a full-screen app with the branded plane icon, and on iOS an installed app is also the only way a web page can send you notifications. (Home-screen tiles are always static images on iOS/Android — the animated logo and favicon live inside the app.)

This page is 100% static — no servers, no accounts, no API keys required. It asks a public reader service to render the Google Flights results page, then parses the prices right here in your browser. If the reader blocks one Google domain, the app automatically tries the next one in the list. Settings are saved in your browser only.

Accuracy first. The app defaults to an exhaustive search: every airport pair, every stay length and every departure date that fits the window is looked up, so the cheapest option it reports really is the cheapest on offer. Time is not a shortcut here — a 5-airport month-long sweep is ~490 lookups ≈ 25–30 minutes key-less. It keeps running in the background (see above), progress is checkpointed and a reload offers to resume.

Date window = whole trip. By default every listed flight departs and returns inside the window you set. Example: with a 6–7 day stay and a window of 06.12.2026–13.12.2026 only 06.12 (6- and 7-day stay) and 07.12 (6 days) can still return in time, so the older departures are not searched or listed — choose “Departure date only” if you want to allow a return after the window.

Why a big search takes a while: the key-less reader serves roughly 20 lookups per minute per visitor (one lookup = one Google Flights page), and answers HTTP 429 past that. Rather than failing, the app queues its lookups under that rate and shows the wait, the elapsed time and an ETA in the progress line. A free reader API key lifts the limit, so paste one here if you want to sweep big airport sets quickly. Setting the ceiling above 0 caps the sweep (departure dates are spread across the window and the result header states exactly what was covered); 0 means exhaustive.
